# SwarmMind 成本报告

文档版本：v1.0  
更新时间：2026-03-18  
文档状态：预算评估稿

## 1. 报告目的

本报告用于回答三个问题：

1. 基于当前代码状态，SwarmMind 继续推进需要多少研发投入。
2. 平台进入内部试点后，每月大致需要多少运行成本。
3. 若进一步走向生产化，成本结构会集中在哪些部分。

本报告采用区间估算，而不是精确财务报价。原因是模型单价、云资源价格、任务规模和 sandbox 策略都会显著影响最终成本。

## 2. 成本结论摘要

从当前仓库状态出发，SwarmMind 的成本结论如下：

1. 从“当前代码基线”推进到“内部试点版”，一次性研发投入建议按 40 万到 80 万人民币估算。
2. 内部试点版上线后的月度运行成本，建议按 1.5 万到 6 万人民币估算。
3. 若推进到生产化、多租户和 Kubernetes 运行时，月度运行成本大概率上升到 6 万到 20 万人民币区间。
4. 整个成本结构中，人力成本仍是第一大项，随后是 LLM 调用成本与 sandbox 计算资源成本。

## 3. 估算前提

以下估算基于当前仓库和设计目标做出假设：

1. 当前代码已经具备控制面和最小执行闭环，因此不是从零立项。
2. 近期目标是内部试点，而不是立即外部商业化。
3. 执行面默认以 Local Sandbox 用于开发、OpenSandbox 用于试点验证。
4. 基础设施默认组合为 PostgreSQL、Redis、Qdrant、对象存储和 API 服务。
5. 模型以商业 API 调用为主，不自训模型。

## 4. 成本分类

SwarmMind 的成本主要由五部分组成：

1. 研发人力成本
2. 云资源与基础设施成本
3. LLM 调用成本
4. Sandbox 执行资源成本
5. 运维、监控与安全治理成本

## 5. 一次性研发投入估算

### 5.1 从当前代码推进到内部试点版

建议团队配置：

1. 后端/平台工程师 2 人
2. AI/Agent 工程师 1 人
3. 兼职 QA 或测试支持 0.5 人
4. 兼职 DevOps 或基础设施支持 0.5 人

建议周期：2 到 3 个月。

按常见全成本口径估算：

1. 后端/平台工程师：4.5 万到 6 万元每人每月
2. AI/Agent 工程师：5 万到 7 万元每月
3. QA/测试支持：2 万到 3 万元每月
4. DevOps 支持：2.5 万到 4 万元每月

综合估算：

1. 2 个月紧凑推进：约 40 万到 55 万元
2. 3 个月稳妥推进：约 55 万到 80 万元

这部分投入主要用于：

1. 执行器深化
2. durable infra 补强
3. 对象存储与监控接入
4. OpenSandbox 试点稳定性验证
5. 关键测试与回归体系建设

### 5.2 若从试点版推进到生产化准备版

新增投入通常包括：

1. 安全与身份体系接入
2. 多租户隔离与配额
3. Kubernetes 运行时
4. 可靠消息/outbox/补偿机制
5. 更完整的审计、监控与运维工具链

建议再预留 60 万到 120 万元研发预算，周期大致 3 到 5 个月。

## 6. 月度运行成本估算

### 6.1 内部开发验证环境

适用场景：少量开发者、低并发、主要使用 Local Sandbox。

月度成本区间：0.5 万到 1.5 万元。

构成参考：

1. API 与 worker 主机：2000 到 5000 元
2. PostgreSQL、Redis、Qdrant、自建对象存储：1000 到 4000 元
3. 日志、监控、备份：1000 到 3000 元
4. 少量 LLM 调用：1000 到 3000 元

### 6.2 内部试点环境

适用场景：10 到 30 名内部用户，日均 100 到 500 个任务，部分任务使用 OpenSandbox。

月度成本区间：1.5 万到 6 万元。

构成参考：

1. API/worker 与基础服务：5000 到 15000 元
2. Sandbox 资源：4000 到 20000 元
3. LLM 调用：3000 到 15000 元
4. 日志、监控、对象存储：3000 到 10000 元

### 6.3 生产化小规模环境

适用场景：多团队使用，日均 1000 个任务左右，需要更强稳定性和隔离。

月度成本区间：6 万到 20 万元。

构成参考：

1. 高可用 API/worker/K8s 集群：2 万到 6 万元
2. Sandbox 计算资源：2 万到 8 万元
3. LLM 调用：1.5 万到 5 万元
4. 数据存储、对象存储、日志监控、安全：1 万到 4 万元

## 7. LLM 成本模型

### 7.1 成本影响因子

LLM 成本主要受四个因素影响：

1. 每个任务触发的模型调用次数
2. 每次调用的输入输出 token 总量
3. 使用的模型档位
4. 是否有缓存、回退和结果复用策略

### 7.2 简化估算公式

可使用以下公式做粗略估算：

月度 LLM 成本 = 月任务数 × 单任务平均 token 消耗 × 每百万 token 折算单价

建议在预算阶段按三档估算：

1. 经济档：50 到 120 元每百万 token
2. 平衡档：120 到 300 元每百万 token
3. 高性能档：300 到 800 元每百万 token

### 7.3 场景测算

场景 A：内部试点轻量任务

1. 月任务数：6000
2. 单任务平均 token：15000
3. 总 token：约 9000 万
4. 月成本：约 4500 元到 7.2 万元，取决于模型档位

场景 B：中等复杂度研发任务

1. 月任务数：9000
2. 单任务平均 token：30000
3. 总 token：约 2.7 亿
4. 月成本：约 1.35 万元到 21.6 万元

为避免预算失真，建议在试点版中埋点统计：

1. Planner token 消耗
2. Execution token 消耗
3. 回退命中率
4. 每任务平均模型调用次数

没有这些真实数据之前，任何 LLM 成本数字都只能视为预算区间，而不是决算值。

## 8. Sandbox 成本模型

### 8.1 成本影响因子

1. sandbox 创建频率
2. 每个 sandbox 生命周期时长
3. 使用本地执行、Docker、OpenSandbox 还是 Kubernetes
4. 任务是否需要联网、依赖安装和较高 CPU/内存配额

### 8.2 建议判断

1. 开发阶段优先使用 Local Sandbox，可显著降低成本。
2. 内部试点阶段对高风险或需留痕任务使用 OpenSandbox。
3. 不建议一开始就把所有任务都迁到高成本强隔离环境。

### 8.3 成本优化手段

1. 使用 profile 分层，区分轻量任务和重任务。
2. 限制默认 sandbox TTL。
3. 控制依赖安装频率，尽量复用镜像。
4. 将纯推理任务留在控制面，不进入 sandbox。

## 9. 隐性成本

除了显性云账单，还需考虑以下隐性成本：

1. 回归测试与故障排查时间
2. 提示词、模型和任务模板持续调优成本
3. OpenSandbox 或 K8s 运行时的问题定位成本
4. 安全合规评审成本
5. 失败任务人工介入成本

如果这些隐性成本不计入预算，平台很容易在试点阶段被低估。

## 10. 成本优化建议

### 10.1 产品与任务策略

1. 优先挑选高价值、可标准化的任务类型做试点。
2. 为任务设置预算和最大重试次数。
3. 区分“必须执行”和“仅生成建议”两类任务，降低高成本执行占比。

### 10.2 技术策略

1. Planner 尽量使用较低成本模型，复杂执行再升级高档模型。
2. 增加缓存、模板回退和 artifact 复用。
3. 用 profile 控制 sandbox 资源规格，避免所有任务都按重型规格运行。
4. 将日志、artifact、replay 分层存储，降低热存储成本。

### 10.3 运维策略

1. 先用单区、低冗余试点环境，验证价值后再扩大投入。
2. 对 LLM、sandbox、数据库建立独立成本看板。
3. 每月复盘任务成功率、平均耗时、平均 token 和平均 sandbox 时长。

## 11. 预算建议

### 11.1 建议的第一阶段预算

如果目标是未来 2 到 3 个月内完成内部试点，建议预算：

1. 一次性研发预算：50 万到 80 万元
2. 试点期 3 个月运行预算：5 万到 15 万元
3. 预备风险金：10 万到 20 万元

合计建议：65 万到 115 万元。

### 11.2 建议的第二阶段预算

如果试点成功，准备走向生产化，建议追加预算：

1. 研发预算：60 万到 120 万元
2. 6 个月运行预算：40 万到 100 万元

## 12. 最终判断

SwarmMind 的成本结构是健康的，原因在于：

1. 当前代码已经完成了相当一部分底座建设，避免了从零投入。
2. 大部分新增支出会直接转化为可见能力：更深执行、更稳基础设施、更强安全治理。
3. 平台既可以低成本从内部试点起步，也能沿同一架构逐步升级。

需要特别关注的是：

1. 不要低估 LLM 与 sandbox 的联动成本。
2. 不要把生产化能力过早压到 MVP 周期里。
3. 要尽快用真实埋点替代拍脑袋估算。

因此，建议采用“先试点、后扩容、再生产化”的预算策略，这也是当前项目最具性价比的推进方式。
